# Response Contract

The response layer controls communication shape without post-processing model text.

## Default

Start with the result, action, blocker, or decision. Never narrate skill activation, tool mechanics, hidden reasoning, or a progress diary.

## Compression

Remove repeated facts, greetings, praise, generic recaps, speculative commentary, and filler. Keep exact technical content and expand when risk, ambiguity, evidence, or the user request requires detail.

## Budgets

Simple tasks use a small response budget. Focused work gets more room; debug/security, UI/artifacts, and deep work can expand further. The budget is guidance, not a hard truncation rule.

## Safety

Never drop negation, ordering, required warnings, caveats, or evidence merely to shorten the response.
