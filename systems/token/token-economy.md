# Token Economy

Token efficiency means removing repeated reasoning and prose, not removing technical substance.

- Use progressive disclosure: load only the context needed for the current decision.
- Keep a compact working set: task, constraints, decisions, evidence, changed paths, and unresolved risks.
- Prefer repository search and targeted reads over broad dumps.
- Reuse verified results; do not repeat the same lookup after state has not changed.
- Collapse repeated tool output and duplicate prose before carrying it forward.
- Preserve exact literals: code, commands, paths, URLs, identifiers, versions, errors, numbers, and negation/order terms.
- Do not summarize away acceptance criteria, security boundaries, compatibility requirements, or failure evidence.
- Do not force compression when the compact form would become ambiguous.

Default loop: select → inspect → decide → act → verify → retain only durable facts.
