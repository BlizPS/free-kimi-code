# UI Generation System

Treat UI as a product system, not a visual mockup.

1. Inspect existing screens, stack, tokens, assets, routes, and interaction patterns.
2. Research one targeted reference when the request names a product/site, requests similarity, or is visually non-trivial. Use current authoritative material when available.
3. Extract patterns instead of copying: hierarchy, density, typography, color roles, spacing, navigation, interaction, state handling, and motion.
4. Define the content model and layout before decorative styling. Use one coherent visual family.
5. Implement behavior and real states first: loading, empty, error, success, disabled, focus, hover, touch, keyboard, and reduced motion where relevant.
6. Stress responsive behavior with long text, missing data, narrow widths, touch targets, and overflow.
7. Verify the rendered result when possible, then polish only observed mismatches.

Avoid generic AI-slop patterns: card soup, pill-everything, giant gradients, excessive glass, decorative icon piles, fake controls, filler sections, oversized heroes, arbitrary shadows, and invented data. Use them only when the product context proves they belong.
